Step4. Streamlit 배포하기

내 컴퓨터에서만 돌아가던 앱을 GitHub와 Streamlit Community Cloud로 인터넷에 공개한다. API 키를 안전하게 숨기는 방법까지 포함한다.

01배포 전 준비물

  1. Step3에서 완성한 app.py (실행이 잘 되는 상태여야 한다)
  2. GitHub 계정 — 없다면 github.com에서 이메일로 가입
  3. 나이스 Open API 인증키 (Step2에서 발급받은 것)

배포는 "내 코드를 GitHub에 올리고 → Streamlit Cloud가 그 코드를 가져가서 실행"하는 방식이다. 그래서 GitHub에 코드를 정확히 올리는 것이 핵심이다.

02requirements.txt 만들기

내 컴퓨터에는 pip install로 설치한 라이브러리가 있지만, Streamlit Cloud의 서버에는 없다. 어떤 라이브러리가 필요한지 파일로 적어둬야 서버가 알아서 설치한다.

requirements.txt (app.py와 같은 폴더에 새로 생성)
streamlit
requests

re는 파이썬에 기본 내장된 모듈이라 따로 적지 않아도 된다.

03API 키를 코드에서 분리하기

지금까지는 API_KEY = "발급받은_인증키"처럼 코드에 직접 키를 적어왔다. 이 상태로 GitHub에 올리면 키가 그대로 공개된다. Streamlit에는 st.secrets라는 별도의 비밀 저장소가 있어서, 코드와 키를 분리할 수 있다.

1. 로컬에 secrets 파일 만들기. 프로젝트 폴더 안에 .streamlit 폴더를 만들고, 그 안에 secrets.toml 파일을 만든다.

.streamlit/secrets.toml
API_KEY = "실제_발급받은_인증키"
참고
.streamlit처럼 점(.)으로 시작하는 폴더는 운영체제 탐색기에서는 안 보일 수 있지만, VS Code 사이드바에서는 정상적으로 보이고 만들 수 있다.

2. app.py에서 secrets로 읽어오도록 바꾸기.

app.py — 수정 전 / 수정 후
# 수정 전
API_KEY = "발급받은_인증키"

# 수정 후
API_KEY = st.secrets["API_KEY"]

이제 실제 키 값은 secrets.toml 파일 하나에만 존재한다. app.py에는 키가 전혀 적혀있지 않다.

04GitHub에 새 저장소 만들기

  1. github.com에 로그인한 상태에서 우측 상단 + 버튼 → New repository를 누른다.
  2. 저장소 이름을 입력한다 (예: meal-notifier). 영문, 숫자, 하이픈만 사용한다.
  3. Public을 선택한다.
  4. Create repository를 누른다.

05GitHub에 파일 업로드하기

저장소가 만들어지면 빈 저장소 페이지에 uploading an existing file이라는 링크가 보인다. 그걸 누르거나, 화면 위쪽의 Add file → Upload files를 누른다.

  1. 내 컴퓨터의 프로젝트 폴더를 연다.
  2. app.py와 requirements.txt, 딱 이 두 파일만 골라서 업로드 화면으로 드래그하거나 choose your files로 선택한다.
  3. 페이지 아래로 내려가서 Commit changes를 누른다.
가장 중요한 규칙
프로젝트 폴더 전체를 통째로 드래그하지 않는다. 폴더째로 올리면 그 안에 있는 .streamlit/secrets.toml(실제 API 키)까지 같이 올라간다.

06GitHub에 잘 올라갔는지 확인하기

저장소 페이지를 새로고침해서 파일 목록을 확인한다. app.py와 requirements.txt만 있어야 하고, secrets.toml이나 .streamlit 폴더는 없어야 정상이다.

github.com/내계정이름/meal-notifier

secrets.toml이 보인다면
당황하지 말고 그 파일을 저장소에서 삭제한다 (파일 클릭 → 휴지통 아이콘 → Commit changes). 이미 공개됐던 키는 나이스 Open API 사이트에서 새로 발급받는 것이 가장 확실하다.

07Streamlit Community Cloud로 배포하기

  1. share.streamlit.io에 접속해 Continue with GitHub로 로그인한다 (GitHub 계정 인증 필요).
  2. Create app (또는 New app) 버튼을 누른다.
  3. Repository에서 방금 만든 저장소를 선택하고, Branch는 main, Main file path는 app.py로 둔다.
  4. Advanced settings를 펼쳐 Secrets 칸에 로컬 secrets.toml과 똑같은 내용을 붙여넣는다.
  5. Deploy!를 누르고 몇 분 기다린다.

08배포 확인하고 공유하기

배포가 끝나면 https://저장소이름-랜덤문자.streamlit.app 형태의 주소가 생긴다. 이 링크는 누구에게나 공유할 수 있고, 받은 사람은 설치 없이 바로 앱을 쓸 수 있다.

meal-notifier-a1b2c3.streamlit.app

코드를 수정하고 싶으면 GitHub 저장소에서 app.py를 클릭 → 연필(편집) 아이콘 → 내용을 고치고 → Commit changes를 누르면 된다. Streamlit Cloud가 변경을 감지해서 자동으로 다시 배포한다.

09자주 만나는 오류

ModuleNotFoundErrorrequirements.txt에 라이브러리 이름이 빠졌다. 오류 메시지에 나온 라이브러리 이름을 추가하고 파일을 다시 커밋한다.
KeyError: 'API_KEY'Streamlit Cloud의 Secrets 설정이 안 됐거나 키 이름이 다르다. 앱 관리 화면(Manage app) → Settings → Secrets에서 확인한다.
화면이 하얗거나 계속 로딩 중Manage app → Logs에서 실제 에러 메시지를 확인한다. 대부분 위 두 가지 중 하나다.
저장소에 secrets.toml이 같이 올라감업로드할 때 폴더째로 드래그했을 가능성이 높다. 06번대로 해당 파일을 삭제하고, 다음부터는 파일을 하나씩 선택해서 올린다.

정리

  • API 키는 코드에 직접 적지 않고 st.secrets로 분리한다.
  • GitHub에는 app.py와 requirements.txt만 올린다 — secrets.toml이 든 .streamlit 폴더는 절대 같이 올리지 않는다.
  • 실제 키 값은 Streamlit Cloud의 Secrets 설정에만 저장된다.
  • 코드 수정은 GitHub 웹 편집기로 하고, Commit하면 Streamlit Cloud가 자동으로 재배포한다.
